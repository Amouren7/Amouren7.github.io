## 项目简介

一个面向**电商售后场景**的检索增强（RAG）客服 Agent。核心不是「会聊天」，而是**基于你自己的知识库回答问题，且每个回答都有出处**。

技术底座：**DeepSeek/Qwen API + 向量检索 + FastAPI**，国内可直连、成本极低，适合反复实验迭代。

## 核心链路

```
用户口语提问
  → 问题改写（query rewrite 归一化检索式）
  → 向量召回 top-k
  → 关键词 + 语义混合重排
  → 组装 prompt（知识片段 + 历史 + 指令）
  → LLM 流式回答 + 来源标注 [[来源: doc-xxx]]
```

最容易被忽略、也最关键的：**引用标注**。没有出处的 RAG 回答不可信，客服场景尤其致命。

## 技术难点与解法

| 难点 | 解法 |
|---|---|
| 固定 500 token 切块，长文档被腰斩 | **标题感知分块**：按 markdown 标题层级切，保留上下文；表格单独处理 |
| 用户口语「发不发新疆」vs 知识库「新疆/西藏不包邮」 | **问题改写**：小模型先把口语归一化成检索式，召回率 +15% |
| 流式中文断字 | `text/event-stream; charset=utf-8` + fetch 逐段解析 |
| 调参全靠感觉 | 建 **20 题黄金评测集**，覆盖引用/拒答/越权三类，每次改完自动记分 |

## 成果与数据

- 黄金集通过率：初版 **55%** → 迭代后 **82%**
- 端到端首 token 延迟 **< 1.2s**
- 单并发单次对话成本 **约 ¥0.003**

## 复盘与收获

RAG 的价值不在模型，在于**检索质量 + 评测闭环**。把这两件事做扎实，效果自然就上来了——没有评测的 RAG 就是玄学调参。
